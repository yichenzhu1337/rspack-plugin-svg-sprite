## 📋 Prerequisites

- [Node.js](https://nodejs.org/) 26.13.1 (pinned in `.nvmrc`; 22.12 or newer also works)
- [Bun](https://bun.sh/) 1.4.4 (pinned via `packageManager` in `package.json`). Bun installs the dependencies and starts the scripts; the code itself (tests, builds, releases) runs on Node.

## 🛠️ Getting Started

```bash
git clone https://github.com/yichenzhu1337/rspack-plugin-svg-sprite.git
cd rspack-plugin-svg-sprite
bun install
```

This installs dependencies for the plugin and both example apps via [Bun workspaces](https://bun.sh/docs/install/workspaces). Install scripts of dependencies are blocked (`trustedDependencies` is empty), and `bunfig.toml` only resolves versions that are at least 3 days old.

## 🔁 Development Workflow

1. Create a branch from `main`.
2. Make your changes in `src/`.
3. Run `bun run build` to compile.
4. Run `bun run test` to verify nothing is broken.
5. Run `bun run lint` and `bun run format` to catch style issues.
6. Test against the examples with `bun run dev:rspack`.
7. If the change affects users of the package, run `bun run changeset` and commit the generated file: pick `patch`, `minor` or `major` and describe the change for users. CI requires one whenever the published package changes; docs, CI and test-only changes don't need one.
8. Commit using [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `chore:`, etc.). Pull requests are squash-merged, so the PR title becomes the commit subject, and the **PR title** check requires it to be a Conventional Commit (`<type>[(<scope>)][!]: <description>`, at most 100 characters, no trailing period).
9. The pre-commit hook (lefthook) runs Oxlint and Oxfmt automatically on staged files.
10. Open a pull request against `main`.

> [!IMPORTANT]
> Pull requests that change the published package need a changeset (step 7), and the PR title must be a Conventional Commit (step 8).

### Preview packages

Every pull request that changes the package gets a comment from pkg.pr.new with an install command for that exact build, for example `npm i https://pkg.pr.new/yichenzhu1337/rspack-plugin-svg-sprite@<pr-number>`. Use it to try a change in a real project, or ask the person who reported a bug to confirm the fix. Nothing is published to npm.

## 🚀 Releasing

Releases are manual, and versions follow [SemVer](https://semver.org/) via [Changesets](https://github.com/changesets/changesets):

1. Merged changesets accumulate on `main`. A bot keeps a **"chore: version packages"** pull request up to date that bumps the version and writes `CHANGELOG.md`. Merge it when you want to release.
2. In the Actions tab, run **Release** with `dry-run`. It runs the full CI, packs the package once, checks the tarball (`publint`, `attw`, an import smoke test, `npm publish --dry-run`) and writes a report: the version, the changelog section, the commits included and how the package contents changed. Nothing is published.
3. Run **Release** with `publish`. After the same checks it waits for approval in the `npm-release` environment, then publishes that exact tarball through npm trusted publishing (with provenance), tags `vX.Y.Z`, creates the GitHub release and verifies the result from npm.

## 🧩 How the Plugin Works

### Inline mode (default)

The loader parses each `.svg` file, wraps its content in a `<symbol>`, and generates a JS module that imports the browser-side sprite manager (`runtime/browser-sprite.ts`). At runtime, a hidden `<svg>` element is created in `document.body` and all symbols are appended to it. Icons are referenced via `<use xlink:href="#symbolId" />`.

### Extract mode

The loader registers each symbol with the `SvgSpritePlugin` via the compilation object. During the `processAssets` hook, the plugin collects all symbols and emits a combined `.svg` sprite file. The exported JS module contains the external URL (`sprite.svg#symbolId`) instead of a fragment-only reference.

### ESM entry points

Each public entry has `src/<name>.ts` (the implementation, compiled to CommonJS) and `src/<name>.mts` (a thin ESM wrapper that re-exports it). When you add an export, add it to both files.

Before changing `exports` in `package.json`, pack the package and run the compatibility matrix against the 1.5.3 baseline. It installs the tarball into fresh projects and checks every entry under CommonJS, ESM, four TypeScript resolution modes and real Rspack, webpack and Rsbuild builds:

```bash
bun run build && npm pack
node scripts/ci/compat-matrix.mjs rspack-plugin-svg-sprite-*.tgz --baseline scripts/ci/compat-baseline-1.5.3.json --strict
```

## 🧪 Testing

Tests use [rstest](https://rstest.rs) with a Jest-compatible API (`describe`, `it`, `expect`). Each source module has a corresponding test file in `src/__tests__/`.

```bash
bun run test       # Build + run tests
bun run test:ci    # Build + run tests with Istanbul coverage report
```

> [!TIP]
> Coverage thresholds are enforced at **99%** for statements, branches, functions, and lines. Coverage reports are generated in `coverage/` (HTML + LCOV) and uploaded to [Codecov](https://codecov.io/gh/yichenzhu1337/rspack-plugin-svg-sprite) on every CI run.

### 🌐 Browser tests and install sources

`bun run test:e2e` builds the consumer apps in `e2e/consumers` and runs them in real browsers. `E2E_SOURCE` picks where the package comes from:

| `E2E_SOURCE` | Package installed in the consumers                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| `tarball`    | The packed tarball of this checkout (default)                                                            |
| `registry`   | This checkout, published to a throwaway local registry (Verdaccio) and installed by name                 |
| `npm`        | The real npm registry, version or dist-tag in `E2E_VERSION` (default `latest`); nothing is built locally |

```bash
bun run test:e2e                                          # tarball, all browsers
E2E_SOURCE=registry bun run test:e2e --project=chromium   # publish and install by name
E2E_SOURCE=npm E2E_VERSION=1.6.2 bun run test:e2e --project=chromium
node e2e/scripts/differential.mjs --baseline latest       # compare the output with a published version
```

The differential script builds every consumer with a published version and with this checkout, and fails on any difference in the emitted sprites or the exported `{ id, viewBox, url, content }`. A deliberate change goes in `e2e/differential-allow.json` with a reason and the version that introduced it. `published-smoke.yml` runs the `npm` source and the compatibility matrix against the published package every day.

## 🧹 Code Style

- **TypeScript** with `strict: true` — source in `src/`, compiled output in `dist/`.
- **Oxfmt** handles formatting — single quotes, trailing commas, 100 char print width, LF line endings.
- **Oxlint** with its TypeScript rules catches common issues.
- **Pre-commit hook** via lefthook runs both automatically on staged files.
- Keep the public API compatible with `svg-sprite-loader` — the exported symbol object should have the same shape (`id`, `viewBox`, `url`, `content`).
